# Single Sign-On Setup and Troubleshooting

## Overview

Northwind Cloud supports Single Sign-On (SSO) using SAML 2.0 and OpenID Connect (OIDC). SSO lets your identity provider (IdP) manage authentication for your Northwind Cloud workspace, so users log in with their existing corporate credentials. This document covers setup for both protocols, required attributes, certificate rotation, common failure modes, SCIM provisioning, and emergency break-glass access. SSO configuration is managed from Workspace Settings, under the Security tab, by a workspace administrator.

## SAML Setup Steps

1. In Workspace Settings, select Security, then choose SAML as the SSO protocol.
2. Copy the Northwind Cloud Assertion Consumer Service (ACS) URL and Entity ID (Audience URI) displayed on the setup page.
3. In your IdP, create a new SAML application and paste the ACS URL and Entity ID into the corresponding fields.
4. Configure the IdP to sign assertions and export the signing certificate in X.509 PEM format.
5. Upload the certificate to Northwind Cloud in the Security tab.
6. Map the required attributes (see below) in your IdP's attribute statement configuration.
7. Save the configuration and run the built in test login before enabling SSO for all users.

## OIDC Setup Steps

1. In Workspace Settings, select Security, then choose OIDC as the SSO protocol.
2. Register a new OIDC application in your identity provider using the redirect URI shown on the Northwind Cloud setup page.
3. Copy the Client ID and Client Secret generated by your IdP into the corresponding fields in Northwind Cloud.
4. Confirm the IdP's discovery document (issuer URL) is reachable and matches the issuer configured in Northwind Cloud.
5. Ensure the scopes openid, email, and profile are requested, plus a custom or standard claim for group membership.
6. Save the configuration and run the built in test login before enabling SSO for all users.

## Required Attributes

Both SAML and OIDC configurations must send the following attributes or claims. Login will fail if either is missing.

| Attribute | SAML name | OIDC claim | Purpose |
|---|---|---|---|
| Email | email or NameID | email | Matches the user to their Northwind Cloud account |
| Groups | groups or memberOf | groups | Maps IdP group membership to Northwind Cloud roles |

Group values should be short, consistent strings (for example, "engineering" or "finance") since role mapping is done by exact string match in the Security tab.

## Certificate Rotation and Expiry Warnings

SAML signing certificates must be rotated every 12 months. Northwind Cloud tracks certificate expiry and sends automated warning emails to workspace administrators:

1. 30 days before expiry: a warning email is sent recommending that rotation be scheduled.
2. 7 days before expiry: a second, higher priority warning email is sent.

If a certificate expires without rotation, SAML logins will fail for all users until a new certificate is uploaded. OIDC configurations do not require manual certificate rotation, since client secrets are managed through the standard OAuth token lifecycle, but administrators should still review OIDC app credentials annually as good practice.

## Common Failures and Troubleshooting

The most frequent issue reported is a redirect loop after the user authenticates at the IdP and is sent back to Northwind Cloud. A redirect loop means assertion validation failed. Check the following, in order:

1. Clock skew: the IdP server and Northwind Cloud must agree within 5 minutes. If the IdP server clock has drifted beyond 5 minutes, assertions will be rejected as expired or not yet valid. Sync the IdP server to a reliable time source.
2. Certificate mismatch: confirm the certificate uploaded in the Security tab matches the current signing certificate in the IdP, especially after a rotation.
3. Audience URI: confirm the Entity ID or Audience value configured in the IdP exactly matches the Entity ID shown on the Northwind Cloud setup page, including trailing slashes and casing.

Other common issues include missing group claims, which will log the user in but leave them without any assigned role, and blocked pop up windows during the initial IdP redirect, which can be resolved by allowing pop ups for the Northwind Cloud domain.

## SCIM Provisioning (Enterprise Only)

SCIM based user provisioning and deprovisioning is available exclusively on the Enterprise plan. SCIM allows your IdP to automatically create, update, and deactivate Northwind Cloud user accounts based on IdP group and user changes, removing the need for manual account management.

To enable SCIM:

1. Confirm your workspace is on the Enterprise plan. SCIM options are hidden on other plans.
2. In Workspace Settings, under Security, generate a SCIM API token.
3. Enter the SCIM base URL and token into your IdP's provisioning configuration.
4. Run a test sync to confirm users and groups appear correctly in Northwind Cloud.

Workspaces on non-Enterprise plans must manage users manually or through SSO group mapping alone.

## Break-Glass Admin Access

Every workspace retains one designated break-glass administrator account that authenticates with a Northwind Cloud username and password instead of SSO. This account exists to restore access if the SSO configuration becomes broken, for example after a certificate expires or an IdP outage occurs. The break-glass account:

1. Is exempt from mandatory SSO enforcement, even when SSO is set as required for all other users.
2. Should use a strong, unique password and, where possible, be protected with a hardware security key.
3. Should be used only for emergency recovery and configuration fixes, not for daily administrative work.

Workspace administrators should test break-glass login credentials periodically to confirm they remain valid before an actual SSO outage occurs.
