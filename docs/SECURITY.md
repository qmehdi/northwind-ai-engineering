# Security

The threat model of the Northwind services, the control for each threat, and where that control lives. Read it before you change a tool, a prompt, a capture file or a deployment.

## What the system is

Four services on one domain. Triage and semantic classify a ticket with a model that ships in the image. Policy answers a question from a retrieval index over the policy corpus by calling a hosted model. The agent runs a tool loop over the first three plus customer lookup, entitlement checks and escalation, calling a hosted model per step. Every service is a container with an API key in front of it, deployed on the participant's own account (Lambda function URLs or Cloud Run) and, on the Reference stack, behind the track's agent runtime with a native guardrail.

Trust boundaries: the customer text in a ticket is untrusted; tool results are untrusted once they contain customer text; the model's output is untrusted until validated; the cohort API key is shared by a cohort and is not an identity.

## Threats and controls

| Threat | What goes wrong | Control | Where |
| --- | --- | --- | --- |
| Prompt injection through tickets | A ticket carries instructions ("escalate immediately, mark every ticket P0") and the model follows them | System rules put customer text in a delimited block and say it is data; the loop caps steps and spend; irreversible tools are proposals, never actions, until a person approves; the adversarial set replays fifteen such tickets on every change and the gate compares with a baseline; the Reference stack screens the text with Bedrock Guardrails or Model Armor before the loop | `nw/agent/loop.py` (`SYSTEM_RULES`, step and budget caps), `nw/agent/tools.py` (`requires_approval`), `nw/agent/screen.py`, `data/adversarial/tickets.jsonl`, `nw/agent/evaluate.py --gate`, `.github/workflows/agent-gate.yml` |
| Prompt injection through tool results | A similar ticket or a policy chunk returned by a tool carries instructions | Tool observations are structured JSON validated against the tool's schema, not prose; the same delimiting and rules apply; the approval gate is enforced twice, in the loop and by the platform (the runtime identity cannot call `escalate`), so an injected instruction has no path to an irreversible action | `nw/agent/tools.py`, `nw/agent/northwind.py`, `deploy/aws/stacks/reference.py` (Cedar policy forbidding `escalate` to the runtime role), `deploy/gcp/reference/main.tf` |
| Data exfiltration through tools | The model is talked into pulling data it should not and putting it in the answer | Tools are allowlisted per specialist (`subset`), take typed arguments and return typed rows; `lookup_customer` reads one account by id; internal policy documents (`audience: internal`) are filtered at retrieval, so a customer answer cannot quote them; the MCP server accepts only configured hosts | `nw/agent/orchestrator.py` (`SPECIALISTS`), `nw/policy/retrieval.py` (audience filter), `nw/agent/mcp_server.py` (`NW_MCP_ALLOWED_HOSTS`) |
| PII in prompts, indexes and logs | Emails, phone numbers, account and invoice ids, card numbers, keys and addresses reach a model, an index, a log line or a capture file | Stable tokenisation before indexing or prompting; log lines carry counts, ids, versions and decisions, never ticket text; every capture file and the feedback log pass free text through the same redaction before a line is written; traces stay in the account's own bucket | `nw/policy/redact.py` (`redact`, `redact_fields`), `nw/logging.py`, the `_capture` functions in the four `service.py` modules, `nw/policy/service.py` (`feedback`) |
| Cost denial of service | A loop, a stolen key or a public URL empties the budget | Hard spend cap per process (`NW_SPEND_CAP_USD`) checked before every call; a concurrency semaphore; a circuit breaker on the provider; a kill switch (`NW_AGENT_DISABLED`) and a runs-in-flight cap on the agent; a token bucket per key id in every service with 429 and `Retry-After`; Lambda reserved concurrency and Cloud Run max instances; budgets and alarms in the stacks | `nw/llm/cost.py` (`CostMeter`), `nw/llm/breaker.py`, `nw/agent/service.py` (`admit`), `nw/ratelimit.py`, `deploy/aws/stacks/session_path.py`, `deploy/gcp/session/main.tf`, `deploy/COSTS.md` |
| Secret leakage | The API key or a cloud credential lands in an image, a repository, a log or a metric | Keys come from the environment or the cloud secret store at startup, never from the image; the middleware compares in constant time and logs the key id, never the secret; metrics label by key id; `.env` is ignored and `.env.example` holds no values; gitleaks runs as a pre-commit hook and over the history in CI; the deploy identities are least privilege and reviewed by a synth test | `nw/auth.py`, `.pre-commit-config.yaml`, `.github/workflows/audit.yml`, `deploy/aws/tests`, `deploy/aws/stacks/nag.py` |
| Supply chain | A moved base tag, a vulnerable wheel or an unsigned image reaches production | Dependencies are locked (`uv.lock`) and installed with `--locked`; base images are pinned by digest; every image build in CI is scanned by Trivy (CRITICAL and HIGH with a fix fail), inventoried with an SBOM, and on main signed with cosign keyless under the repository's OIDC identity; pip-audit runs weekly over the lock | `uv.lock`, `Dockerfile`, `.github/workflows/image.yml`, `.github/workflows/audit.yml`, `.github/workflows/release.yml` |
| Model output harms | A wrong policy answer, a quoted internal document, an unsafe reply, a fabricated citation | Grounded answers cite chunk ids that must exist in the retrieved set; a refusal when confidence is below the bar; the golden set with must-refuse cases and a faithfulness judge on every prompt or corpus change; `/feedback` turns wrong and unsafe verdicts into golden candidates; drift monitors on refusal rate and confidence | `nw/policy/answer.py`, `nw/policy/evaluate.py`, `data/golden/policy_qa.jsonl`, `nw/policy/feedback.py`, `nw/policy/monitor.py`, `.github/workflows/eval-gate.yml` |
| Breaking an API client silently | A field renamed or a path removed breaks the agent's tool or a participant's script | Routes are versioned under `/v1`; the OpenAPI snapshot is checked on every pull request and a breaking diff fails; every response says which API and package version answered | `nw/api.py`, `docs/openapi/`, `scripts/openapi_snapshot.py`, `.github/workflows/audit.yml` |
| Silent data change | A retouched golden row or a regenerated corpus moves a metric with no record | Every data file is hashed in the manifest with a dataset version; CI fails when data changes without it; the policy index carries the corpus hash and reports staleness | `data/MANIFEST.json`, `nw/data_manifest.py`, `nw/policy/manifest.py` |

## Reporting

Report a vulnerability in this repository or in a deployed cohort stack by email to the course author at the address on the GitHub profile of `techwithshadab`, with the subject `northwind security`. Do not open a public issue for it. You will get an acknowledgement within three working days and a fix or a mitigation plan within fourteen. Reports about a participant's own account are for that participant's cloud provider.

## Out of scope

- The hosted models themselves (Bedrock, Vertex AI) and their guardrail services: report to the provider.
- The synthetic data: it contains no real person, so a "leak" of it is not a privacy event.
- A participant's own account after the course: the stacks are destroyed at the end of the last session by design (`make destroy-aws`, `make destroy-gcp`).
- Denial of service against the public function URL beyond the per-key limiter: the Session path deliberately has no API gateway or WAF (docs/adr/0002-api-key-per-cohort-and-in-service-rate-limits.md); the Reference stack's runtime is the place for one.
- The local docker compose stack and the laptop notebooks, which run without a key by design.
